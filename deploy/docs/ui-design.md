# UI Design Notes

> 更新时间：2026-06-03
> 用途：记录 Nanmuli Blog 前端视觉方向与管理端设计约束。
> 注意：本文件是设计参考，不代表当前功能完成度；功能状态以 `README.md` 和 `docs/trial-release-roadmap.md` 为准。

---

## 当前设计目标

Nanmuli Blog 当前是个人技术博客和技术日报管理系统。MVP Beta 阶段的 UI 应优先服务真实使用：

- 公开站点需要清晰展示文章、技术日志、项目、技能和日报。
- 管理后台需要稳定完成内容管理、系统配置、采集任务、日报生成和质量查看。
- 日报和自动优化页面要强调状态、结果、失败原因和质量趋势。
- 视觉风格可以有技术感，但不能牺牲可读性和管理效率。

## 设计原则

| 原则 | 说明 |
|------|------|
| 内容优先 | 文章正文、日报条目、来源链接和质量指标必须易读 |
| 管理高效 | 管理端应减少装饰，优先表格、筛选、状态、操作反馈 |
| 状态明确 | loading、empty、error、disabled、success 状态必须完整 |
| 响应式 | 公开站点和管理端核心页面都要适配桌面和移动端 |
| 可维护 | 复用 Element Plus 和已有组件，不引入额外 UI 框架 |

## 公开站点

公开站点适合保持克制的现代技术博客风格：

- 首页突出文章和最近内容，不做过度营销式 hero。
- 文章页优先保障 Markdown 排版、代码块、目录和阅读体验。
- 技术日报页应突出日期、章节、来源和摘要。
- 项目和技能页可以适度增强视觉层次，但避免影响加载速度。

## 管理后台

管理后台是 MVP Beta 的核心使用界面，优先级高于装饰性页面。

管理后台页面应具备：

- 顶部或侧边导航。
- 表格筛选和分页。
- 明确的主操作按钮。
- 批量操作时有确认和结果反馈。
- 异步任务有状态、进度、错误信息和重试入口。
- 配置页面有说明、默认值、保存反馈和危险项提示。

## 日报系统页面

日报页面需要重点展示：

- 任务状态：pending、running、completed、failed。
- 生成日期、触发方式、耗时。
- 章节内容和来源链接。
- 质量评分、弱点、优化建议。
- 最近质量趋势。
- 失败原因和重试操作。

## 自动优化页面

自动优化页面不宜只展示一段文本建议，应逐步补齐：

- 历史评分趋势。
- 弱点分类。
- 已采用策略和效果。
- 下一轮建议策略。
- 采集源健康状态。

## 色彩和风格

当前建议采用轻量、清晰、技术感适中的配色：

- 主色：蓝或青蓝，用于链接、按钮和状态强调。
- 辅色：绿色用于成功，橙色用于警告，红色用于错误。
- 背景：浅色模式优先，暗色模式可作为后续增强。
- 管理端避免大面积高饱和渐变。

详细配色参考见 `color-schemes.md`。

## 后续设计优化方向

1. 为日报质量趋势补充图表组件。
2. 为采集任务补充可展开的步骤日志。
3. 为系统配置增加分组说明和配置风险提示。
4. 为公开日报页面增加来源可信度和更新时间展示。
5. 为移动端管理页面优化表格折叠和操作入口。
