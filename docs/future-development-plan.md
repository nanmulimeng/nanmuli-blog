# 未来开发计划

> 版本：v1.0  
> 日期：2026-06-03  
> 当前基线：MVP Beta 试用版

## 总体方向

后续开发目标不是盲目堆功能，而是围绕三个方向逐步增强：

1. **稳定上线**：让博客、日报、自动优化、crawler-service 在真实环境中稳定运行。
2. **质量提升**：让日报质量持续变好，减少重复、泛化内容和无效来源。
3. **服务复用**：让 crawler-service 成为可被少量内部服务复用的可靠 HTTP 服务。

## 阶段规划

### 阶段 1：MVP Beta 试用稳定化

目标：保证当前版本能持续、可观察、可恢复地运行。

优先任务：

- 观察连续 3 个工作日日报生成结果。
- 修复日报完成态进度显示和任务终态展示细节。
- 完善管理端失败状态、错误信息和重试入口。
- 记录失败来源、低质量来源、重复来源。
- 固化上线检查清单和回滚步骤。

验收标准：

- 连续 3 个工作日日报生成成功。
- Backend、Crawler、Frontend 健康检查稳定。
- 日报失败时能在管理端定位失败原因。
- 公开端最新日报可访问。

### 阶段 2：日报质量提升

目标：让日报从“能生成”变成“稳定可读、来源清楚、重复少”。

优先任务：

- GitHub Trending 展开到 repo 级 URL。
- `tech_article` 过滤定义页、下载页、营销页、泛化教程页。
- 增加来源质量白名单和黑名单。
- 增强 RSS/官方工程博客来源。
- 增加日报条目事实检查提示，不做强事实核查但提高可追溯性。
- 优化 Prompt，要求输出更具体的技术变化、影响和适用场景。

验收标准：

- 重复 source URL 明显下降。
- 每期至少有 1 条高质量技术文章。
- 每条核心条目都有清晰来源。
- 管理员人工审查时可接受率持续提升。

### 阶段 3：自动优化强闭环

目标：让自动优化真正改变下一次采集策略。

优先任务：

- 将 `digest_final_eval` 的 weakness 转成 structured action。
- 为低语言覆盖增加跨语言补采策略。
- 为来源重复增加强去重和来源分散约束。
- 为低质量 `tech_article` 增加站点约束和页面类型惩罚。
- 为每次策略调整记录原因，便于趋势页展示。
- 增加“上一期弱点 -> 本期调整 -> 本期得分”的对照视图。

验收标准：

- 同类弱点连续出现时，系统必须展示策略调整。
- 趋势 API 能返回策略变化原因。
- 测试覆盖最终评估影响下一轮计划。

### 阶段 4：Crawler Service 独立接入增强

目标：让博客之外的第二个内部服务可以稳定使用 crawler-service。

优先任务：

- 补充 API key 管理说明。
- 明确任务创建、轮询、删除、重试、导出的接口契约。
- 明确 callback payload、重试策略、失败语义。
- 增加 client 接入示例。
- 增加服务级限流、并发预算和超时建议。
- 增加错误码文档。

验收标准：

- 新服务只需 base URL + API key 即可创建任务并查询结果。
- callback 可选，不影响任务完成。
- 博客系统仍作为普通 client 正常运行。

### 阶段 5：运维观测与安全

目标：降低试用期排查成本，提高上线安全边界。

优先任务：

- 增加 trace id 串联 Backend、Crawler、AI 调用。
- 增加最近失败来源列表。
- 增加 scheduler 状态和最近执行记录。
- 增加 AI 调用耗时、tokens、失败率统计。
- 前端 dev/build 工具链升级到安全版本。
- 完善 `.env` 模板和敏感配置检查。
- 增加备份/恢复文档。

验收标准：

- 管理员能在 3 分钟内判断问题属于 AI、搜索、源站、配置、回调还是部署。
- 生产环境不包含真实密钥在仓库中。
- 关键服务异常可通过日志快速定位。

### 阶段 6：内容产品化增强

目标：让日报更像可长期阅读和沉淀的技术内容。

候选任务：

- 日报一键转技术日志或文章草稿。
- 条目收藏、忽略、标记低质量。
- 管理端人工修订日报后再发布。
- 基于历史日报做主题趋势回顾。
- 增加月度技术趋势总结。
- 将高质量条目沉淀为知识库索引。

验收标准：

- 日报不只是一次性信息流，而能成为博客内容素材。
- 管理员可以低成本筛选和沉淀有价值内容。

## 优先级矩阵

| 优先级 | 类型 | 任务 |
| --- | --- | --- |
| P0 | 上线稳定 | `.env` 配置、健康检查、手动触发日报、公开端可访问 |
| P0 | 安全 | 禁止真实 `.env` 入库、callback key 非空、crawler API key 非空 |
| P1 | 质量 | repo URL 展开、tech_article 过滤、来源效能记录 |
| P1 | 自动优化 | weakness 转 structured action |
| P1 | 运维 | 失败来源列表、scheduler 状态、trace id |
| P2 | 工具链 | Vite/vue-tsc 大版本升级 |
| P2 | 产品 | 日报修订、收藏、转日志/文章 |
| P3 | 长期 | 知识库、趋势回顾、语义搜索 |

## 不建议当前做的事

- 不建议立即做 SaaS 多租户。
- 不建议把 crawler-service 暴露为公网开放服务。
- 不建议在 MVP Beta 期强行做复杂事实核查。
- 不建议为了 dev audit 立即无准备升级 Vite 8/vue-tsc 3。
- 不建议在日报质量尚未稳定前自动公开发布到所有渠道。
